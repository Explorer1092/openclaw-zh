# 会话修剪

会话修剪在每次 LLM 调用之前从上下文中裁剪**旧的工具结果**。它可以减少工具输出（exec 结果、文件读取、搜索结果）积累导致的上下文膨胀，而不会影响你的对话消息。

<Info>
修剪仅在内存中进行——它不会修改磁盘上的会话记录。你的完整历史记录始终保留。
</Info>

## 重要性

长时间运行的会话会积累大量工具输出，导致上下文窗口膨胀，增加成本，并可能比必要的时间更早触发[压缩](/concepts/compaction)。

修剪对于 **Anthropic 提示缓存**尤其有价值。缓存 TTL 过期后，下一个请求会重新缓存完整提示。修剪可减小缓存写入大小，从而直接降低成本。

## 工作原理

1. 等待缓存 TTL 过期（默认 5 分钟）。
2. 查找旧的工具结果（用户消息和助手消息不会被处理）。
3. **软修剪**过大的结果——保留头部和尾部，插入 `...`。
4. **硬清除**其余部分——用占位符替换。
5. 重置 TTL，使后续请求能够重用新缓存。

## 智能默认值

OpenClaw 为 Anthropic 配置文件自动启用修剪：

| 配置文件类型           | 是否启用修剪 | 心跳    |
| ---------------------- | ------------ | ------- |
| OAuth 或 setup-token   | 是           | 1 小时  |
| API 密钥               | 是           | 30 分钟 |

如果你设置了显式值，OpenClaw 不会覆盖它们。

## 启用或禁用

对于非 Anthropic 提供商，修剪默认关闭。要启用：

```json5
{
  agents: {
    defaults: {
      contextPruning: { mode: "cache-ttl", ttl: "5m" },
    },
  },
}
```

要禁用：设置 `mode: "off"`。

## 修剪与压缩

|          | 修剪               | 压缩                |
| -------- | ------------------ | ------------------- |
| **功能** | 裁剪工具结果       | 总结对话            |
| **保存** | 否（按请求临时）   | 是（保存在记录中）  |
| **范围** | 仅限工具结果       | 整个对话            |

两者互为补充——修剪在压缩周期之间保持工具输出精简。
