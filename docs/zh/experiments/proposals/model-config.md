# 模型配置(探索)

本文档捕获关于未来模型配置的**想法**。这不是发布规范。对于当前行为,请参见:
- [模型](/concepts/models)
- [模型故障转移](/concepts/model-failover)
- [OAuth + 配置文件](/concepts/oauth)

## 动机

操作员希望:
- 每个提供程序多个身份验证配置文件(个人与工作)。
- 简单的 `/model` 选择与可预测的回退。
- 文本模型和具有图像能力的模型之间的明确分离。

## 可能的方向(高级别)

- 保持模型选择简单: `provider/model` 带可选别名。
- 让提供程序具有多个身份验证配置文件,具有显式顺序。
- 使用全局回退列表,以便所有会话一致地故障转移。
- 仅在显式配置时覆盖图像路由。

## 待解决的问题

- 配置文件轮换应该是每个提供程序还是每个模型?
- UI 应该如何为会话呈现配置文件选择?
- 从遗留配置键的最安全迁移路径是什么?
