# 统一运行时流式传输重构计划

## 目标

为 `main`、`subagent` 和 `acp` 提供一条共享的流式传输管道，使所有运行时获得完全一致的合并、分块、投递排序和崩溃恢复行为。

## 背景

- 当前行为被拆分在多个特定于运行时的整形路径中。
- 格式化/合并 bug 可能在某条路径中修复，而在其他路径中依然存在。
- 投递一致性、重复抑制和恢复语义难以推断。

## 目标架构

单一管道，运行时专属适配器：

1. 运行时适配器仅发出规范事件。
2. 共享流组装器对文本/工具/状态事件进行合并和最终化。
3. 共享 Channel 投影器统一应用各 Channel 的分块/格式化。
4. 共享投递账本强制执行幂等发送/重放语义。
5. 出站 Channel 适配器执行发送并记录投递检查点。

规范事件约定：

- `turn_started`
- `text_delta`
- `block_final`
- `tool_started`
- `tool_finished`
- `status`
- `turn_completed`
- `turn_failed`
- `turn_cancelled`

## 工作流

### 1) 规范流式传输约定

- 在核心层定义严格的事��� Schema 与验证。
- 添加适配器约定测试，确保每个运行时发出兼容的事件。
- 尽早拒绝格式错误的运行时事件并输出结构化诊断信息。

### 2) 共享流处理器

- 用一个处理器替换特定于运行时的合并器/投影器逻辑。
- 处理器负责文本增量缓冲、空闲刷新、最大分块拆分和完成刷新。
- 将 ACP/main/subagent 的配置解析合并到一个辅助函数中，防止配置漂移。

### 3) 共享 Channel 投影

- 保持 Channel 适配器简洁：接受最终化的块并发送。
- 将 Discord 特有的分块特殊处理移至 Channel 投影器中。
- 在投影之前保持管道与 Channel 无关。

### 4) 投递账本与重放

- 为每个 turn/chunk 添加投递 ID。
- 在物理发送前后记录检查点。
- 重启时幂等地重放待处理的 chunk，避免重复投递。

### 5) 迁移与切换

- 第一阶段：影子模式（新管道计算输出，但由旧路径发送；进行对比）。
- 第二阶段：逐运行时切换（`acp`，然后 `subagent`，然后 `main`，或按风险反向排列）。
- 第三阶段：删除遗留的特定于运行时的流式传输代码。

## 非目标

- 本次重构不涉及 ACP 策略/权限模型的更改。
- 不在投影兼容性修复之外扩展特定 Channel 的功能。
- 不涉及传输/后端重新设计（除非事件一致性需要，否则 acpx 插件合约保持不变）。

## 风险与缓解措施

- 风险：现有 main/subagent 路径出现行为回归。
  缓解措施：影子模式差异对比 + 适配器约定测试 + Channel 端到端测试。
- 风险：崩溃恢复期间出现重复发送。
  缓解措施：持久化投递 ID + 投递适配器中的幂等重放。
- 风险：运行时适配器再次产生分歧。
  缓解措施：所有适配器强制使用共享约定测试套件。

## 验收标准

- 所有运行时通过共享流式传输约定测试。
- Discord ACP/main/subagent 对微小增量产生等效的间距/分块行为。
- 崩溃/重启重放对同一投递 ID 不发送重复 chunk。
- 遗留的 ACP 投影器/合并器路径已删除。
- 流式传输配置解析已共享，与运行时无关。
